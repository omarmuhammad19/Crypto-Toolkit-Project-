How it works

AES-256 uses a shared secret key for both encryption and decryption. The output is Base64-encoded and includes the IV (Initialization Vector) for security. DES uses a 64-bit key; 3DES applies DES three times for stronger security; AES-256 is the modern standard.

Reference

About the Algorithms

Brief explanations of each cryptographic algorithm and technique implemented in this toolkit.

Symmetric

AES — Advanced Encryption Standard

A block cipher operating on 128-bit blocks with 128, 192, or 256-bit keys. This toolkit uses AES-256 in CBC mode — the global encryption standard, used in TLS, banking, and government systems.

Symmetric

DES — Data Encryption Standard

A 64-bit block cipher with a 56-bit effective key length. Now considered insecure due to its short key size, but historically significant. Replaced by 3DES and later AES.

Symmetric

3DES — Triple DES

Applies DES three times (encrypt → decrypt → encrypt) with two or three different keys, yielding 112–168 bits of effective security. A bridge between DES and AES, still used in legacy banking systems.

Asymmetric

RSA — Rivest–Shamir–Adleman

Public-key cryptosystem based on the difficulty of factoring large integers. A public key encrypts data; only the matching private key can decrypt it. 2048-bit keys are the current minimum recommendation.

Encoding

Base64

Encodes binary data as 64 printable ASCII characters. Not encryption — it's reversible without a key. Used for transmitting data over text-based protocols like email and HTTP.

Encoding

Hexadecimal & URL Encoding

Hex encodes each byte as two hex digits (00–FF). URL encoding replaces unsafe characters with %XX sequences, enabling safe transmission of data in URLs and HTTP forms.

Hashing

SHA-256 & SHA-512

Members of the SHA-2 family. SHA-256 produces a 256-bit digest; SHA-512 produces 512 bits. Cryptographically collision-resistant and widely used in digital signatures, certificates, and blockchain.

Salted

Salted Hashing

Prepends a random "salt" value to the input before hashing. This prevents pre-computed rainbow table attacks, ensuring that the same password hashed twice yields different results.
